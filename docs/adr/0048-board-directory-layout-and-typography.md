# ADR 0048: Board directory layout and typography

**Date:** 2026-10-12
**Status:** Accepted
**Refines:** The visual fidelity treatment in ADR 0028; the rail and shared
creation row in ADR 0046 remain authoritative.

## Context

The owner supplied two current Boards screenshots and requested Impeccable's
layout, typeset and distill passes. The introduction and view furniture gave
more weight to the page explanation than to the boards being browsed. The
wide toolbar wrapped density onto another line, then repeated the selected
category order and board total below it.

## Decision

- Preserve the centered Imladris column, existing heading and introductory
  copy, all four self-hosted families, semantic colors and every native form
  or link. This is a refinement of the existing visual world.
- Use the established Display, Title, Body, Small, Fine, Meta and caps roles,
  with a shorter introductory stack and deliberate 16/24/32px spacing roles.
  Counts and timestamps remain tabular data.
- Give the wide viewing row two explicit groups: all six orders, then Peek
  Off/3/5. The selected choice has the existing gold underline grammar.
  Remove the redundant visible Viewing caption and the separate Peek capsule.
  Accessible group names, current/pressed states and focus halos remain.
- Place density and useful ranking explanations in one supporting row.
  Category order needs no repeated explanation; totals appear once in the
  introduction. Ranking, selection persistence and shareable URLs are unchanged.
- Let descriptions and topic-preview titles wrap. Board names use connected
  line spacing; empty-preview helpers are quieter. Every board, preview and
  viewing action retains a 44px target. Compact hides descriptions and tightens
  spacing while preserving the reader's explicit Peek choice.
- Keep the phone's native inline disclosure, enhanced sheet, focus containment,
  dismissal and viewport handoff. Distinguish its current choice with strong
  semantic ink and the regular Marcellus weight that is actually supplied.
- Keep adaptations outside the reviewed compatibility transfer. Rebuild delivery
  assets and reconcile the application digest under the existing asset contract.

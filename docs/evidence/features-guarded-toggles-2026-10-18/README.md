# Guarded feature-flag toggles evidence (`/admin/features`, ADR 0049)

Local verification of the guarded per-row feature-flag toggles on `/admin/features` (ADR 0049, `ADMIN.md` §9.3, `docs/runbooks/operations.md` §2). The grouped inventory tables, summary tiles, filters, and unknown-overrides table remain intact; each declared-flag row gains one native `<details>` confirmation inside `td.features-flag-cell` that names the consequence, side-effect warning, and exact `settings.features` write before committing a single-flag POST and same-transaction audit entry.

## Two-connection lock probe (`validation/lock-probe.log`)

Tested on MariaDB 11.8.9 (`retroboards_ft_conc`) with two concurrent connections: Connection A reads `settings.features`, holds the transaction for 1.5s, and writes `alpha=false`; Connection B starts 0.3s later and writes `beta=false`.

- **`variant=lock` (shipped `SettingRepository::lockForUpdate()` — no-op upsert + `SELECT … FOR UPDATE`):**
  - `row=missing`: Connection B blocks on the row lock for 1.20s, reads `{"alpha":false}`, and commits `{"alpha":false,"beta":false}`.
  - `row=existing` (`{"email":false}`): Connection B blocks for 1.20s, reads `{"email":false,"alpha":false}`, and commits `{"email":false,"alpha":false,"beta":false}`.
- **`variant=gaplock` (plain `SELECT … FOR UPDATE` without prior upsert):**
  - `row=missing`: both connections read `[]` at 0.00s and then collide on the insert; MariaDB aborts Connection B with `SQLSTATE[40001]: Serialization failure: 1213 Deadlock found`, so its write fails and only `{"alpha":false}` is stored. With `row=existing` this variant serializes correctly, which is why the shipped variant adds the upsert.
- **`variant=nolock` (unserialized read, then write):**
  - Connection A fails on MariaDB with `SQLSTATE[HY000]: General error: 1020 Record has changed since last read in table "settings"` after B commits. Not measured on MySQL, where the same sequence is expected to let A overwrite B's committed change from a stale read, losing B's write silently.

## Review and mutation check

The planned four-reviewer adversarial review (backend, UX, copy, process) was interrupted twice and returned no verdicts, so there is no independent reviewer sign-off to cite. Its saved probes were triaged in the main session and each confirmed finding was fixed:

- **Readiness filter hid the changed row.** A success redirect now drops a `readiness` filter the changed row no longer matches (live-computed rows such as `link_previews` change category when switched), as it already dropped `state`.
- **A stored number outside the float range made every write a 500.** The write now refuses with a 422 and leaves the stored text alone. The loader is unchanged: it still applies the rest of that map, so a rolled-back flag never silently returns. An earlier draft of the fix also treated such a map as corrupt in the loader, which would have ignored every override app-wide; `test_a_number_php_cannot_write_back_keeps_its_overrides_applied_and_refuses_only_the_write` pins the correct behaviour and fails against that draft.
- **"Written back exactly" was not literally true** (other keys pass through `json_decode`/`json_encode`). The ADR, runbook and service docblock now say "preserved through the JSON round trip".
- **No-op attribution could credit the wrong change.** It is now credited only while the recorded result still matches both the effective state and the stored override; direct SQL/CLI edits leave no audit row, so it stays best-effort and the wording says so.
- **Catalog copy.** Six entries (`engagement`, `notifications`, `moderation_queue`, `community`, `oauth`, `tags`) were corrected against runtime behaviour the review probes exercised.
- **Mutation survivors.** [`validation/mutation-spot-check.log`](validation/mutation-spot-check.log) applies 16 single-edit mutants to the final tree, one at a time, against `AppAdminFeatureToggleTest` alone: all 16 are killed, including the dropped CSRF field, a `return` field that ignores filters, a dropped controller admin check and 404, a dropped service admin check and cache invalidation, and the attribution mutants. Two earlier survivors, removing the transaction and removing `FOR UPDATE`, cannot be seen from a single connection inside the test harness's outer transaction and were not re-run; the lock probe above is their evidence.

## Recorded doc-vs-code discrepancies (findings not modified in this slice)

During the 57-flag code trace for `FeatureFlagCatalog`, the following places where existing comments or runbooks differed from runtime code were recorded so the confirmation copy follows runtime truth:
- **`engagement`:** FeatureFlags::DEFAULTS describes engagement as 'reactions, stars, per-thread unread' (src/Core/FeatureFlags.php:27), but the code also gates the whole /inbox surface, which is the hard-coded post-sign-in destination (src/Controller/Controller.php:60-63).
- **`notifications`:** docs/runbooks/operations.md:36-38 calls a false override a rollback 'without a data change', but with the email workers still running, queued instant emails and digests are marked suppressed and digest windows advance (src/Worker/NotificationEmailWorker.php:99-100,144; src/Worker/DailyDigestWorker.php:82-90). operations.md:89-92 (section 3) does warn to pause the workers instead.
- **`email`:** docs/runbooks/operations.md:36-38 calls a false override a rollback 'without a data change', but running workers mark queued instant, digest and announcement emails suppressed while email is off (src/Worker/NotificationEmailWorker.php:70,75,99-100,144) and consume digest windows (src/Worker/DailyDigestWorker.php:82-90). operations.md:89-92 (section 3) agrees with the code.
- **`mentions`:** src/Support/MentionLinker.php:11-14 says links and notifications 'toggle as a unit', but links are baked into stored body_html at write time, so existing links stay while off and mentions written while off stay unlinked after re-enabling.
- **`search`:** docs/runbooks/operations.md:120-125 says to keep the search flag off until a FULLTEXT rebuild completes, implying the flag stops index use; composer # suggestions still call SearchService::search (src/Service/ComposerSuggestionService.php:165-168), gated only by rich_composer (src/Controller/ComposerController.php:46-48).
- **`announcements`:** docs/runbooks/operations.md:36-38 says a false override takes the subsystem offline, but the live site banner keeps rendering from settings.site_announcement with no flag check (src/Core/App.php:892-903 at HEAD 1a9ac166; templates/layout.php:86).
- **`rich_composer`:** docs/runbooks/operations.md:36-38 says rolled-back routes 404; POST /composer/preview answers 403 JSON instead (src/Controller/ComposerController.php:27-29). docs/runbooks/server_drafts.md:22-24 calls local autosave independent and always working, but it lives in composer.js, which loads only with rich_composer (templates/layout.php:125).
- **`drafts`:** docs/runbooks/server_drafts.md:22-24 says browser-local autosave (drafts flag) is independent and always works; in code it needs rich_composer (composer.js loads only then, templates/layout.php:125), and server-draft sync in the composer requires drafts as well (public/assets/composer.js:23-26).
- **`server_drafts`:** docs/runbooks/server_drafts.md:22-24 presents server_drafts as independent of the drafts flag; public/assets/composer.js:23-26 only syncs when drafts is on, and the no-JS server-draft list lives on /drafts, which 404s when drafts is off (src/Controller/DraftController.php:23-25).
- **`uploads`:** docs/runbooks/operations.md:36-38 says rolled-back routes 404; POST /upload answers 403 JSON 'Uploads are disabled.' and /media/{id} delivery stays live (src/Controller/MediaController.php:34-36,138-163).
- **`anti_abuse`:** FeatureFlags::DEFAULTS describes anti_abuse as 'central limiter, content filters, holds, audit' (src/Core/FeatureFlags.php:45), but the rate limiter is not gated by it (src/Service/RateLimitService.php has no flag reference; bound at src/Core/App.php:1359-1363 at HEAD 1a9ac166), so rate limits keep applying while off.

## Evidence limits

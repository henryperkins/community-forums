# Browser performance evidence — 2026-09-20

> Historical evidence from 2026-09-20, organized on 2026-09-23. Production state, timings, build identifiers and source line references describe that snapshot; they were not remeasured during cleanup. See the [provenance and archive inventory](../../workspace-cleanup/2026-09-23/README.md).

The browser harness is [browser-measure.cjs](browser-measure.cjs). It uses the installed Playwright Chromium build and browser PerformanceObserver/Navigation Timing/Resource Timing APIs, with CDP network records. Chrome DevTools MCP was unavailable; the session brief explicitly allows Playwright performance APIs. All browser production actions are navigation and automatic GET subresources. No production login, POST, configuration, or deployment is part of this track.

The mobile profile is a 390 × 844 CSS-pixel viewport, DPR 2, mobile touch/UA, fourfold CPU throttling, and CDP network settings of 150 ms latency, 1.6 Mbps down, and 750 Kbps up. Network latency emulation does not make these a field percentile or reproduce a real mobile device. A fresh browser context starts with empty client caches; a second navigation reuses that context. Production page starts are separated by at least 30 seconds. Local collection ends seven seconds after `load`, except the explicit 65-second poll capture; production collection ends 15 seconds after `load`. `LCP` is the last observed candidate, and `CLS` is the maximum standard 5-second session window with gaps shorter than one second, excluding entries whose `hadRecentInput` is true. Long-task sums are reported as observed task time and excess over 50 ms, not Lighthouse TBT.

The trace keeps first interim response time and final response header time separately. HTML TTFB uses `navigation.finalResponseHeadersStart`, falling back to `responseStart` only when the final field is unavailable. This matters because production emits HTTP 103 Early Hints. A curl first-byte time or `responseStart` alone can measure the 103 rather than the HTML 200.

On the initial local home trace, app CSS finishes at 3,389 ms and LCP is 3,524 ms: 44.3 ms final HTML wait + 3,344.7 ms elapsed to the last core stylesheet + 135.0 ms to LCP = 3,524.0 ms. These are non-overlapping critical-path intervals, not isolated causal savings. On the local first-unread thread, the same split is 47.4 + 3,356.2 + 192.4 = 3,596.0 ms. The large middle interval reflects uncompressed local delivery and must not be transported to the production attribution table.

The two pollers issue GETs immediately when their corresponding DOM elements exist (`public/assets/app.js:70`, `:110`, `:116`, `:139`, `:224`). The unthrottled [65-second member home trace](../../workspace-cleanup/2026-09-23/README.md#archived-scratch) (`browser-local-member-polls.json`, archived) records the first bell and presence requests at 98.5 and 98.7 ms, before FCP/LCP at 140 ms; their durations are 6.4 and 8.9 ms. Second requests start at 60,114.2 and 60,114.5 ms. The code schedules the next poll 60 seconds after success, pauses when hidden, resumes immediately, and backs off on network/429 errors (`public/assets/app.js:76-110`). Deferring the initial poll has no measured production LCP saving in this audit. It could remove two overlapping PHP requests from the load burst; pricing that saving needs an authenticated production replay or a controlled production-like concurrency experiment.

The first-unread member thread also requests the lazy editor entry at 3,567.7 ms, the Milkdown adapter at 4,471.5 ms, `/composer/giphy-config` at 7,004.9 ms, and `/api/drafts/~2Ft~2F1~2Freply` at 7,010.7 ms. The adapter completes at 6,950.9 ms. The Giphy endpoint returns 404 for this local fixture, while the draft GET returns 200. There are no recorded non-GET requests. This shows the additional composer request chain and does not establish that the same feature/configuration is active for an authenticated production user.

The dominant included local thread layout shift is 0.087002 when the composer dock shrinks from 207.75 to 67 pixels at 7,065 ms, after editor hydration. `composer.js:2764-2767` waits for the adapter before enhancing the form; `composer.js:2670` applies the dock marker only during the eventual expansion setup; `app.css:1825-1854` applies the compact geometry. The six late font loads contribute only about 0.000626 to their own CLS window. An earlier raw 0.640335 entry in the first visit has `hadRecentInput: true` and is excluded by the CLS calculation; it is preserved in the raw file. Reserving compatible dock geometry earlier is a layout-stability candidate, with **zero established LCP saving** and a regression risk to no-JS behavior and editor-failure fallback. It would need mobile no-JS, failed-entry/failed-adapter, restored draft, keyboard, and dock-expansion verification. No behavior was changed.

## Code facts checked against current checkout

`templates/layout.php:49-53` declares the two core stylesheets, a 517-byte minified editor stylesheet whenever WYSIWYG is enabled, optional package-theme CSS, and optional dynamic brand CSS. The third tiny editor stylesheet is distinct from the two core payloads. `/brand.css` emits `public, max-age=300` without ETag in `src/Controller/BrandingController.php:29-69`; this is a conditional risk, not evidence that production currently waits on it.

`src/Core/App.php:416-431` emits preload Links for the two core CSS files, app.js, and EB Garamond 400. The final HTTP 200 Link header alone cannot improve the HTML waiting period; an observed HTTP 103 can. Fifteen self-hosted WOFF2 faces are declared with `font-display: swap` and a Latin unicode range (`public/assets/imladris.css:25-39`). Actual loaded faces depend on visible content; the local home loads four and the local thread loads seven, including the preloaded face. Downloading all fifteen fonts is not an observed page-load cost.

The core scripts are classic deferred scripts (`templates/layout.php:96-99`). `composer.js:186-196` and `:2757-2767` initiate the editor import only when a real composer input exists; `src/client/wysiwyg/index.ts:5-7` loads the heavier adapter. This is already a shipped optimization. The Worker serves allowlisted `/assets/*` using its Assets binding and sets hashed URLs to one-year immutable caching (`worker/assets.mjs:7-27`), bypassing the PHP container. Therefore a font burst is not evidence of PHP-container concurrency in the current production build.

## Production asset and poll details

All four production HTML responses and the CSS/JavaScript responses use `Content-Encoding: zstd`. Hashed assets return `public, max-age=31536000, immutable`, `X-RetroBoards-Cache: STATIC`, and edge `HIT` where exposed. The third editor stylesheet has 517 decoded bytes and 322 encoded bytes; core CSS encoded bodies total 86,778 bytes on the home sample (20,429 + 66,349), versus 480,465 decoded bytes. The two previously documented gzip sizes are local gzip measurements, not the actual zstd transfer sizes.

Each navigation receives an HTTP 103 carrying the four preload Links. On a cold browser visit those files are fetched before the final HTML and subsequently appear in the document record as cache reuse. Their per-document `transferSize` is zero, despite the initial browser cache being empty. Do not report the raw resource-transfer sum as the complete initial wire transfer. The cold home sum of encoded resource bodies is 220,649 bytes; the cold thread sum is 2,432,769 bytes, of which the image is 2,166,961 bytes. These sums reconstruct referenced compressed payload sizes, not a packet capture or all protocol overhead. The actual pre-HTML early-hint download start/end times are not present in the per-document resource record.

There are no `/brand.css` or package-theme requests in either production page. Home uses five fonts and thread seven, each including the preloaded EB Garamond face. Remaining fonts finish after first paint and contribute only small shifts. No lazy editor entry or adapter is requested by the two guest pages. The global `composer.js` and `passkeys.js` scripts still load, but no measured costly editor bundle is present on these guest visits. Cloudflare injects an external Analytics beacon attempt, which the existing same-origin CSP blocks; the trace records zero transferred bytes for it. `/cdn-cgi/speculation` is a separate 151-byte GET. Neither is a material measured delay.

On cold home, the final HTML header wait is 642.7 ms, the last stylesheet completes at 861.8 ms, and FCP/LCP occurs at 996 ms. The additive split is 642.7 ms + 219.1 ms to last stylesheet + 134.2 ms to paint. The last stylesheet is the tiny editor CSS, discovered after HTML. The last core stylesheet is already available at 694.7 ms, making the extra stylesheet's completion tail 861.8 − 694.7 = **167.1 ms**. A 103-preloaded stylesheet or conditionally omitting it when no editor exists could remove some of that tail; 167.1 ms is an observed upper bound, not a measured intervention. The 134.2 ms paint interval overlaps a 103 ms long task whose call attribution is unavailable. On warm home, final HTML headers account for 683.6 / 756 = 90.42% of LCP; all residual client work totals 72.4 ms.

Production guests render the presence widget but no bell. The four automatic presence GET durations are **535.9, 491.9, 494.2, and 430.4 ms**, each exceeding the 300 ms target under this lab profile; start times are 873.0, 724.6, 1,673.4, and 1,326.8 ms. No production authenticated bell or member initial-poll pair was measured. The local authenticated trace above verifies simultaneous immediate starts and the 60-second schedule, but does not establish production member poll latency or contention.

## Browser recommendations with quantified limits

1. **Serve responsive image derivatives while retaining the original and the live read gate.** Repository-owned; needs authorized implementation and normal attachment/privacy verification. The offline [benchmark](browser-image-benchmark.json) resampled this exact image to 640 × 349 with GD 2.3.3 and WebP quality 82: **2,166,961 → 37,432 bytes**. The [reviewable derivative](browser-media-1-640-q82.webp) is 98.27% smaller and supports the measured 279 CSS-pixel slot at DPR 2. The original is unchanged in scratch. At 1.6 Mbps = 200 bytes/ms, the transfer-only saving is `(2,166,961 − 37,432) / 200 = 10,647.645 ms`. Keeping all other intervals constant gives estimated cold LCP `13,636 − 10,647.645 = 2,988.355 ms`, still above 2.5 seconds. This is not an end-to-end variant replay. Local resize+encode took 48.2 ms on this host; do not assume that duration on the production half-vCPU container. Generate/reuse variants outside the critical GET where practical. Risks are text readability, alpha/color fidelity, storage/CPU, and incorrect public caching of restricted media. Verify responsive widths, DPR 1/2, zoom/original access, held/private/deleted parents, and an actual cold browser trace with the new variant.
2. **Make the known above-fold LCP image discoverable without waiting for lazy layout, and preserve intrinsic image dimensions from trusted attachment metadata.** Repository-owned. Its observed discovery window is 1,661.6 − 1,353.0 = **308.6 ms maximum**, including unavoidable HTML transfer/parsing; any actual gain will be smaller. Do not combine this ceiling with the entire render-blocking saving again, because those intervals overlap. The direct LCP saving from width/height alone is **not established**. Apply eager/high priority only when the renderer knows that an image is likely above the fold; blanket eager loading risks slowing long threads. Keep lazy loading for later images and verify with text-first posts, several images, mobile and desktop layouts, and no-JS navigation.
3. **Avoid the post-paint mobile rail geometry change.** Repository-owned, with no measured LCP saving; potential layout-stability gain is the observed **0.445833 CLS** window. Preserve the functional stacked no-JS navigation and CSP while establishing enhanced layout before first paint. A new blocking script can trade CLS for extra LCP, so measure both and do not adopt it without before/after evidence. Verify deep links, warm and cold assets, disabled/broken JavaScript, keyboard navigation, and both rail positions.
4. **Conditional editor CSS delivery or an additional preload.** Repository-owned, observed cold home upper bound **167.1 ms**. The stylesheet is unused on the measured guest routes, but dynamic inbox composer insertion still needs it when an editor appears. The code change must preserve those later insertion and failed-import cases. On warm home the whole client remainder is only 72.4 ms, so a 167 ms repeat-visit claim would be incorrect. Verify all composer contexts and perform a controlled cold home replay.
5. **Initial-poll scheduling is secondary to the image and server round trips.** Removing the immediate duplicate shell refresh could reduce the number of overlapping dynamic requests by two for a member, but measured production LCP saving is **unestablished**. The brief classifies changing poll behavior as a human decision. Preserve hidden-tab handling, resumption, feature-dark 404 stop, errors/backoff, and 60-second freshness if separately approved. Do not rank this as a proven multi-second LCP fix.
